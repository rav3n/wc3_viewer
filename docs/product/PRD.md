# PRD: WC3 Replay Analyzer (рабочее название)

Статус: черновик v0.1 · 2026-10-27

## 1. Цель и проблема

**Цель.** Браузерный анализатор реплеев Warcraft 3 (`.w3g`), который показывает, *как* шёл матч во времени: экономика, механика, билд-ордер, герои, армия. Уровень глубины — как у SC2-инструментов (sc2replaystats, Spawning Tool, Scelight). Пользователь бросает файл, всё считается на клиенте, без сервера.

**Проблема.** Существующие WC3-инструменты отвечают на вопрос «кто выиграл и с чем», но не «почему».

Что отдаёт W3Champions по матчу (проверено через API `website-backend.w3champions.com/api/matches/{id}`):

- метаданные: карта, длительность, MMR до/после, расы, страна, пинг;
- герои: тип и итоговый уровень;
- итоговые агрегаты из игрового экрана счёта: `unitsProduced`, `unitsKilled`, `largestArmy`, `heroesKilled`, `itemsObtained`, `mercsHired`, `expGained`, `goldCollected`, `lumberCollected`, `goldUpkeepLost`.

Чего там нет:

- **временных рядов** — ни одного графика по ходу игры;
- билд-ордера и таймингов (тир, герои, экспансия);
- APM и механики (хоткеи, распределение действий);
- порядка прокачки скиллов и покупок по времени;
- сравнения двух игроков бок о бок.

Чтобы получить это сейчас, игрок пересматривает реплей в клиенте игры вручную. Это долго и не даёт цифр.

**Наше отличие:** таймлайн и производные метрики из потока команд реплея, честно разделённые на «точно» и «оценка».

## 2. Персоны и сценарии

| Персона | Кто | Ключевые сценарии |
|---|---|---|
| **Автор / разработчик** | Играет в ладдер, строит инструмент для себя | Разобрать свой проигрыш: где отстал по таймингам, когда просел APM. Проверить корректность парсера на своих реплеях |
| **Сильный ладдер-игрок** | Высокий MMR, системно улучшает игру | Сравнить свой билд с билдом соперника/про-игрока бок о бок. Найти «дыры»: простой главного здания, поздний второй герой, спам вместо полезных действий |
| **Кастер / тренер** | Комментирует турниры, разбирает игры учеников | Быстро получить ключевые тайминги и поворотные моменты для разбора. Показать ученику график и конкретную минуту. Поделиться экраном/скриншотом |
| **Широкая аудитория** | Казуальные и средние игроки | Кинуть реплей и получить понятную сводку без настройки. Увидеть 2–3 главных вывода, а не стену цифр |

## 3. Каталог метрик

### Что есть в `.w3g` и чего нет

`.w3g` содержит заголовок (карта, игроки, слоты, расы, версия), а дальше — поток команд игроков по тикам: приказы способностям/юнитам с целями (точка или объект), смену выделения, назначение и выбор хоткей-групп, покупки, передачу ресурсов, чат, выход из игры.

**Состояния игры нет.** Нет событий «юнит родился/умер», нет ресурсов, нет HP. Поэтому:

- **точно** — то, что напрямую является командой (APM, хоткеи, приказы, выбор скиллов, покупки);
- **оценка** — то, что выводится из команд через справочник юнитов (стоимость, время постройки, food). Приказ не гарантирует результат: могло не хватить ресурсов, постройку могли отменить или уничтожить.

Все стоимости, время постройки, food, время исследований берутся **из игровых данных** (SLK/таблицы баланса конкретного патча), а не прописываются руками. Справочник версионируется по патчу.

### Таблица метрик

Обозначения: **Т** — точная, **О** — оценка. Персоны: А — автор, Л — ладдер-игрок, К — кастер/тренер, Ш — широкая аудитория.

### Нереализуемо из реплея

- Собранные золото и дерево, текущий банк ресурсов.
- Фактическое появление юнита/здания (только приказ и расчётное завершение).
- Смерти юнитов и зданий, потери в боях, убийства.
- HP, мана, опыт и точный уровень героя (только нижняя граница по скиллам).
- Исход боя и тем более «кто выиграл бой».
- Позиции юнитов (известны только точки, куда отдали приказ).
- Видимость, туман войны, разведка (видел ли игрок противника).
- Время реакции на события.
- Точный результат крипинга: убитые лагеря, выпавшие предметы.

Часть этих цифр W3Champions показывает как итоговые агрегаты (см. раздел 1). Мы их из `.w3g` не получим.

## 4. Экраны MVP

**Загрузка.** Drag-and-drop или выбор файла. Прогресс парсинга. Ошибка с понятной причиной: не 1v1, неподдерживаемая версия, повреждён файл.

**Обзор матча.**

- Шапка: игроки, расы, карта, длительность, версия, результат (если определён).
- Карточки бок о бок: герои с порядком, средний APM/EPM, тир-тайминги, время экспансии.
- 2–3 автоматических вывода: «второй герой на N с позже», «простой главного здания X с» (с пометкой «оценка»).

**Timeline / графики.**

- Общая ось времени для всех графиков, синхронный курсор.
- Графики: APM/EPM, рабочие, supply с линиями 50/80, траты, произведённая армия.
- Маркеры событий на оси: тиры, герои, экспансия, кандидаты в бои.
- Оценочные ряды визуально отличаются (пунктир/штриховка) и подписаны «оценка».

**Билд-ордер бок о бок.**

- Две колонки (игрок 1 / игрок 2), строки по времени.
- Для каждой позиции: время приказа, иконка, название, расчётное завершение, supply на момент приказа (оценка).
- Отменённые позиции — зачёркнуты.
- Фильтры: здания / юниты / исследования / герои / предметы.

**APM-разбор.**

- APM vs EPM по времени, доля спама.
- Action-type breakdown (общий и по фазам игры).
- Хоткей-группы: какие используются, тепловая карта «группа × время», частота переключений.

**Герои.**

- По каждому герою: время появления, порядок скиллов с временем, нижняя граница уровня по времени.
- Покупки и использование предметов на оси времени.

## 5. Нефункциональные требования

**Только клиент.** Без бэкенда и без отправки реплея на сервер. Kotlin/JS, Compose Multiplatform Web, Clean Architecture: парсер и расчёт метрик — в domain/data-слоях без зависимости от UI.

**Скорость.** Целевые значения (проверить на реальных реплеях, файлы есть в `Replay_2026_10_25_2224/`):

- парсинг и расчёт типичного 1v1-реплея — до 1 с на среднем ноутбуке;
- UI не блокируется при парсинге (Web Worker или порционная обработка);
- первая загрузка приложения — бюджет размера бандла надо зафиксировать (открытый вопрос).

**Версии игры.**

- Приоритет — текущие версии, на которых играет ладдер W3Champions (Reforged, 1.32+).
- Классика (до 1.32) — позже и по возможности. Форматы различаются: в Reforged есть дополнительные блоки метаданных, менялись ID и данные баланса.
- Справочник данных юнитов привязан к версии патча из заголовка. Неизвестная версия — берём ближайший справочник и показываем предупреждение.

**Офлайн.** После первой загрузки работает без сети (PWA/Service Worker). Справочники данных — в бандле.

**Надёжность парсера.** Незнакомые типы действий не роняют разбор: пропускаем и логируем. Регрессионный набор реплеев по версиям и расам.

**Приватность.** Реплей не покидает браузер. Аналитику использования, если будет, — без содержимого реплея.

## 6. Риски и открытые вопросы

**Риски**

1. **Оценки расходятся с реальностью.** Без смертей supply, армия и рабочие завышены после первого боя. Митигация: показывать как «произведено», явно маркировать «оценка», на supply — дисклеймер.
2. **Справочник данных.** Нужно извлекать данные баланса для каждого патча W3Champions. Если это делается вручную — ошибки и отставание от патчей.
3. **Формат Reforged.** Публичная документация формата неполная. Каждый патч может менять детали. Нужен регрессионный набор реплеев.
4. **Kotlin/JS + Compose Web.** Размер бандла и производительность графиков на длинных матчах. Готовых графиковых библиотек под Compose Web мало.
5. **Пороги EPM.** Без согласованного правила фильтра спама EPM будет спорным для сильных игроков и кастеров.
6. **Крипинг.** Требует своей базы лагерей по картам ладдер-пула, которую надо обновлять при смене пула.

**Открытые вопросы**

1. Правило EPM: какие повторы считать спамом и с каким интервалом? Ориентироваться на какой-то существующий инструмент?
2. Окно сглаживания APM-графика (30 с? 60 с?) и настраиваемо ли оно.
3. Откуда брать данные баланса по патчам: извлекать из файлов игры своим скриптом или брать из открытых источников?
4. Минимальная поддерживаемая версия Reforged. Нужна ли классика вообще?
5. Как определять результат матча, если в реплее нет однозначного блока результата? Допустимо ли «не определён»?
6. Можно ли (опционально, из браузера) подтянуть итоговые агрегаты W3Champions по матчу, чтобы калибровать оценки? Это не бэкенд, но внешний запрос — согласуется ли с принципом «всё на клиенте»?
7. Нужен ли шаринг результата (ссылка, скриншот, экспорт) в MVP для кастеров, если нет сервера?
8. Что делать с реплеями не 1v1: отказ или частичный разбор?
9. Нужна ли локализация (RU/EN) в MVP?
10. Крипинг: стоит ли вести базу лагерей для ладдер-пула уже в v2?

## 7. Роадмап

**MVP — один матч 1v1**

- Парсер `.w3g` для текущих версий ладдера W3Champions.
- Справочник данных баланса для текущего патча.
- Метрики MVP из раздела 3 (APM/EPM, хоткеи, билд-ордер и тайминги, герои и предметы, оценки экономики и армии).
- Экраны: загрузка, обзор, timeline, билд-ордер бок о бок, APM-разбор, герои.
- Офлайн-работа.

**v2 — глубже по одному матчу + сравнение**

- Мультиматч: загрузка нескольких реплеев, тренды игрока (APM, тайминги по расе/матчапу).
- Сравнение с эталонным реплеем.
- Крипинг-маршруты (с базой лагерей), карта активности.
- Смерти героев по воскрешениям, мульти-задачи, чат.
- Экспорт/шаринг (картинка, файл).

**Дальше**
